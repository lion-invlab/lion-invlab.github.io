## 1. 靜態基準

- HTML：289,060 字元、3,359 行。
- `<style>`：95 個，其中 head 內 65 個、body 內 30 個。
- `<script>`：10 個。
- ID：139 個，唯一 ID 139 個；靜態掃描未發現重複 ID。
- `!important`：約 2,000 次。
- `addEventListener`：約 20 次；內嵌事件屬性約 6 次。
- 媒體查詢有多種不同斷點：380、390、480、520、560、600、640、700、900、1099、1100、1200px 等；需統一設計斷點時逐項驗證，不能直接粗暴刪除。
- 導覽錨點共 13 個（12 個主版面 + 歷史早報捷徑），靜態掃描未發現導覽指向不存在的 ID。
- 活頁採用自訂 radio + label 結構，未使用 ARIA tab role；重構時須保留鍵盤與原生 radio 的可操作性，並驗證標籤和 panel 對應。

## 3. 高風險依賴與不可直接刪除項目

1. 有 30 個 style 區塊位於 body 內；不可直接將 95 個 style 合併後刪除原節點，因為部分 style 節點具有 ID 並可能被腳本定位。
2. 已找到以下樣式節點 ID 同時被腳本引用，需在 CSS 遷移時維持相容，或先修改並測試相依腳本：
   - `tac-layout-hint-v9`
   - `tac-layout-v10`
   - `tac-toolbar-hand-target-v15`
3. 大量 `!important` 和重複選擇器顯示有多輪覆蓋修正；不可只靠格式化或機械式去重，否則會改變層疊結果。
4. 多個活頁由 radio 的 checked 狀態與相鄰選擇器控制；改 DOM 順序、class 或 input/label 關係可能導致切換失效。
5. 靜態檢查不能證明 Safari／Chrome 的實際畫面、點擊行為、資料載入及窄螢幕表現正常。瀏覽器實測仍是必要驗收項目。

## 4. 優先整併的樣式區域

1. **市場情緒／CNN 指標標題與卡片**：多個規則重複覆蓋 #sentiment、.sent、.sbox 與 CNN 標題；需保留深色面板、同心圓、玻璃反光等已核准特色，再合併成單一元件規則。
2. **FOMC 會議面板**：多輪規則反覆調整 .fc-fomc、利率卡、會議日期與觀察區的尺寸／排列；必須以現況 DOM 和已核准畫面確認最終樣式。
3. **主版面標題與紅色標記**：存在多個版本的主標題選擇器與 pseudo-element 標記規則；應合併成一個共用標題元件，並保留市場情緒面板的白色標題例外。
4. **歷史早報工具列**：日期欄、按鈕、工具提示與手機版排列在多個區塊反覆修正；須保留 iOS Safari 日期欄與觸控提示行為。
5. **經濟／財報行事曆**：收折按鈕、狀態標籤、財報 EPS／營收卡片有多個修正版本；需以實際展開／收合狀態做回歸測試。
6. **產業債匯商品報價**：不同活頁的商品名稱、報價、漲跌幅多次補字級／欄位規則；應共用列元件但保留各活頁資料欄位差異。

## 5. 執行決策

- 第一階段只建立獨立設計系統檔案與候選 HTML，不改動唯讀基準檔。
- 新設計系統以 tokens、site shell、panel、heading、tabs、cards、disclosure、data rows、responsive、documented exceptions 分層。
- 先把共用元件定義成獨立 class；逐個主版面遷移時再加上 class，避免尚未驗證就用全域選擇器一次覆蓋所有內容。
- 先試點，再逐步擴大；每批都需做內容、互動、桌機／手機回歸檢查。
- 若沒有可執行的瀏覽器測試環境，需明確標示為靜態驗證，不能聲稱視覺驗收通過。
