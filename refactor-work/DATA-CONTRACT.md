# TAC 投資早報｜固定／動態／條件式資料契約 v1

狀態：**v1.0 結構契約已凍結，供重構施工使用；不是正式母版或每日報告。**
凍結範圍：固定版面、動態欄位責任、條件式狀態及雙母版差異邊界。各資料來源、報價口徑、公式與選稿細節仍以最新專案規則為準；本文件不取代資料來源登記表。  
依據：獨立重構分支 `tac-design-system-work-2026-10-24` 的 2026/10/26 審核版結構，以及最新專案規則。遇到舊交接文件與近期明確指示衝突時，以較新的明確指示為準；視覺重構不得自行改寫資料來源、報價口徑、公式或內容選稿規則。

## 1. 全站共同契約

### 固定（不得因每日更新而改變）

- Header、導覽列、主版面順序、12 個主版面識別、每個主版面的標題、活頁名稱、欄位排列、字級層級、顏色 tokens、卡片外殼、互動方式與響應式規則。
- 主版面與活頁的 DOM／ID／label-for／radio-name 契約；除非有獨立的互動遷移方案，不改變現有控制器與 panel 關係。
- 漲跌顏色：上漲紅、下跌綠；中性或休市使用中性色，不以顏色暗示未核實方向。
- 資料來源、口徑、計算方式、排序方式及內容篩選規則屬業務契約，不是設計層可以任意更改的外觀細節。
- 來源、方法、計算依據等次要說明優先放入收折區，讓主畫面保留可掃讀的最終答案。

### 動態（每次產製必須重新核實）

- 報告日期、各市場各自的資料日期、查詢／截圖時間、數值、漲跌幅、新聞、經濟事件、財報結果、機率、觀察文字、關鍵價位、來源連結及來源更新時間。
- 圖釘／摘要／觀察等評論必須依最終核實的數據同步更新；補齊缺漏數據後，不可保留與新數據矛盾的舊評論。
- 不可沿用母版示例值當成當日值；不可把舊資料冒充當日收盤，也不可混用盤中、收盤、結算、現貨、ETF、銀行牌告等不同口徑。

### 條件式（由日期、交易狀態或資料狀態決定）

- 週一版保留「上週經濟行事曆」與「上週財報行事曆」；週二至週五版只移除這兩個區塊。兩版其餘共用架構、CSS、JavaScript、Dashboard、導覽、連結與功能必須一致。允許差異僅限這兩個區塊、母版識別標記及母版標題。
- 市場休市：標示「休市」及原因，不顯示前一交易日報價冒充當日行情。行情日期依各市場實際交易日判斷，不按星期推定。
- 經濟／財報行事曆必須區分「已公布、今天、即將公布」及真正空資料狀態。
- 「尚未公布」「沒有排定事件」「資料來源暫時無法取得」「已公布但實際值未核實」是四種不同狀態，不得共用同一個空白或提示。
- 某個值未能可靠核實時，明確標註待核／無可靠資料；不得用估值補值或靜默沿用舊值。

## 3. 版面與資料的責任邊界

- **HTML／CSS 設計系統負責：** 面板外殼、標題、活頁尺寸與狀態、卡片、留白、響應式、收折、空狀態視覺與可讀性。
- **資料更新流程負責：** 取得資料、核實來源、交易日期、時區、數值口徑、計算、排序、新聞去重與評論生成。
- **母版差異層負責：** 週一／週二至週五僅保留允許的三類差異（兩個上週區塊、識別標記、標題）。
- 視覺重構不得改動來源優先順序、公式、排序、資料池或評論邏輯。若需修改業務規則，必須先另列變更項、理由、影響面與獨立驗收。

## 4. 各資料元件共用狀態

每個動態資料元件至少須能區分：

1. `loaded`：已核實且可顯示資料。
2. `market-closed`：市場休市，顯示休市與原因。
3. `not-yet-published`：事件尚未公布。
4. `no-scheduled-event`：該時段確實沒有排定事件。
5. `needs-verification`：來源／日期／口徑尚未核實。
6. `source-unavailable`：來源暫時無法取得；不可把它當作「無資料」。
7. `stale-snapshot`：可顯示最後核實快照，但必須明確顯示資料日期／時間。

不得只用空字串、`null` 或一個「暫無資料」文字代表所有狀態。
