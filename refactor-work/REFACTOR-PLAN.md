## 1. 最高優先級原則

1. **成品視覺品質只能比目前驗收版更精美，不得退步。**
2. 不得為了整潔而犧牲資訊密度、可讀性、TAC 的專屬金融研究風格或既有視覺特色。
3. 不得破壞既有內容、資料更新邏輯、資料來源、頁籤、收折、導航及歷史早報功能。
4. 目前驗收版是唯讀參照。所有修改只在本獨立工作分支和獨立路徑進行；不得修改正式首頁或來源驗收檔。
5. 未經檢查與測試，不得宣稱功能完成；不得以新增覆蓋式 CSS 熱修補掩蓋重構問題。
6. 重構範圍以版面架構、共用設計系統和元件一致性為主。資料擷取／計算邏輯原則上保持不變；既有資料缺陷另行記錄，不混入本次視覺重構。

## 4. 固定、動態、條件式三類定義

### A. 固定規格
- 全站字體階層、主色／中性色、上漲紅／下跌綠規則。
- 頁面容器寬度、主版面間距、標題樣式、卡片基礎結構、邊框、圓角、陰影和焦點狀態。
- 活頁標籤高度、字級、選取／hover／focus 狀態與窄螢幕行為。
- 收折區、表格、數據卡、來源揭露、技術說明、提示與空資料狀態的共用樣式。
- 響應式斷點、避免水平溢出的原則、觸控操作尺寸。
- 導覽、頁尾、品牌元素和內部教育訓練標示。

### B. 動態內容
- 行情、價格、漲跌幅、指標數值、排名、殖利率、匯率、商品報價。
- 新聞標題、時間、來源、摘要與分類。
- 經濟／財報行事曆事件、前值、預估、實際、公布狀態與重要性。
- FedWatch 快照、FOMC 相關資料、每日總結及今日觀察文字。
- 所有由外部資料源或每日製作流程更新的數值與文字。

動態資料必須留在原有資料流程中。重構時不得以示範值取代真實欄位，也不得把動態數值硬編碼進共用樣式。

### C. 條件式結構與狀態
- 週一顯示上週經濟行事曆與上週財報行事曆；週二至週五版本按既定規則移除這兩個主版面及其導航／專用引用。
- 活頁切換狀態、收折展開狀態、日期選擇、來源說明展開狀態。
- 無資料、資料尚未公布、休市、來源暫時不可用等狀態。
- 桌機／手機版差異與窄螢幕時的版面重排。

條件式顯示必須由明確結構或規則控制，不可仰賴零散覆蓋式 CSS。

## 5. CSS／JavaScript 重構原則

建議的 CSS 分層：
1. Design tokens：顏色、字體、間距、圓角、陰影、層級。
2. Base/reset：全站基礎規則。
3. Site shell：頁首、導覽、主容器、頁尾。
4. Shared components：主版面標題、卡片、活頁、收折、表格、提示、來源揭露。
5. Panel-specific styles：只有內容本身確有特殊視覺需求時才保留。
6. Responsive rules：集中管理斷點與手機版規則。
7. Documented exceptions：每個例外必須有原因與適用範圍。

JavaScript 原則：
- 先建立事件與 DOM 依賴清冊，識別重複事件綁定、重複功能及選擇器依賴。
- 不改寫資料來源、計算公式或更新流程，除非發現阻擋功能的缺陷且有單獨記錄。
- 移除任何舊程式前，先證明無引用並完成回歸測試。
- 不以「合併 script/style 標籤數量」作為成功指標；可維護性、可預測性與驗收結果才是標準。

## 6. 視覺升級標準

重構後與基準版比較，必須同時達到：
- 主版面之間更一致，但不同內容類型仍保有合適的視覺差異。
- 字級階層、對齊、留白、資訊密度、數據辨識度和閱讀動線更清楚。
- 精緻度至少不低於現版；TAC 專屬金融研究風格與既有核准的特色不得被通用模板取代。
- 桌機與手機都需精緻，不能只縮小桌機版。
- 不得出現內容遺失、版面擠壓、雙欄異常、橫向溢出或操作區重疊。
- 若只讓程式碼變乾淨但視覺變平淡，驗收不通過。

## 8. 已知重構風險（施工前必須處理）

- 原始檔含 95 個 style 區塊與 10 個 script 區塊，存在多輪預覽／修補樣式；已抽取 legacy cascade 保留順序，並以瀏覽器驗證第一輪試點；舊規則尚未全面清除。
- 多處選擇器使用高特異性與版本註解；需要判定實際覆蓋關係及依賴。
- 多個活頁由自訂 input/label/panel 結構控制，靜態搜尋未必能辨認全部標籤；必須核對 DOM。
- 靜態掃描未發現重複 ID，但仍需測試事件、選擇器與動態內容。
- 第一輪主版面與頁籤試點已通過瀏覽器渲染／互動驗收；整體 12 面板的內層資料卡、收折與完整視覺升級仍未完成，不可視為正式交付。
