# TAC 投資早報｜正式工作規則（必讀）
版本：1.6（2026-10-29 MOVE 指定來源與雙母版強制驗證規則）
建立日期：2026-10-28
適用範圍：TAC 投資早報日常製作、獨立審核預覽、資料更新、版面修正及驗收
規則優先級：以使用者最新明確指示為最高；本文件集中記錄穩定規則。若新指示變更規則，先更新本文件並註明變更，再執行。

## 0. 每次工作開始前的強制步驟
1. 先讀取本文件，再核對 GitHub 上實際存在的檔案、分支及內容；不得只憑聊天記憶或檔名推測。
2. 明確記錄本次工作目標、現階段母版、輸出檔案及禁止修改的檔案。
3. 確認報告日期、台灣時區（UTC+8）、星期情境、截稿時間及最近一個已完成的美股交易日。
4. 若母版、路徑、資料或指示有矛盾，先查證已知紀錄及 repo；不得自行另造版型。
5. 執行過程應自主推進：可在權限內查資料、修改、測試、排錯、重試，不需每一步等待使用者說「繼續」。只有需要使用者授權、缺少必要私人輸入或存在無法安全推斷的決策時才停下。
6. 計畫、檔案寫入成功、commit 成功、Pages 部署成功、內容驗收通過是不同狀態；不得混為一談。

## 3. 每日日期情境
- 星期一與星期二至星期五是不同製作情境，必須按報告日套用正確版型語境與行事曆。
- 週一：依已核實的上一個美股交易日收盤資料做週初總覽，並依規則處理上週經濟與財報行事曆。
- 週二至週五：以最近一個已完成的美股交易日為行情基準；導航列不顯示「上週經濟行事曆」及「上週財報行事曆」。經濟／財報行事曆須依當日台灣時間與實際發布狀態，正確區分「已公布／已發布」、「今日公布」、「即將公布」，不得沿用過期狀態。
- 台灣時間與美東時間換算須依當時夏令／冬令時間計算，寫清楚當地日期與台灣日期；不可只按日期字串猜測。

## 4. 市場數據與分析
- 報價必須對應清楚的商品、交易日、時區、價格口徑（正式收盤、結算、盤中、現貨或期貨）及來源。
- 「今日行情」不得混用前一日收盤、盤中價、不同合約月份或不同平台時間快照。
- 以最近一個已正式完成的美股交易日作為主要指數分析基準。不得把尚未收盤的盤中資料當作收盤。
- 儘最大可能補齊關鍵數據：優先查官方／原始來源，再以可信第二來源交叉核對；若仍無法核實，明確標示「待核實」，不得猜測或用舊數字冒充最新值。
- 當指數、產業 ETF、利率、匯率、能源、貴金屬或其他關鍵數據更新後，必須同步重算或修訂摘要、市場觀察、關鍵價位、支撐／壓力、圖釘評論及核心結論；不得留下與新數據矛盾的舊評論。
- 關鍵價位須以同一基準交易日的已核實 OHLC 計算，並標示基準日；計算公式與來源放在既有收折區，不得以無來源數字填補。
- 未核實的數值不可讓評論寫得像已確認；數據缺漏時，分析須明確說明限制與可能情境。

## 5. 新聞篩選與來源
- 優先來源：鉅亨網、Investing.com；國際重大事件可用 Reuters、AP 等原始報導／可信來源交叉核對。
- 時間窗以台灣時間、原始發布時間為準，不可用搜尋排序時間、爬取時間或最後更新時間替代原始發布時間。
- 週一：從前一個美股交易日台灣時間 12:00 起，至本次實際截稿時間。
- 週二至週五：從前一日台灣時間 12:00 起，至本次實際截稿時間。
- 每則新聞應核對原始發布時間、時區、最後更新時間、來源與原文連結；時間窗外舊聞不得假裝新消息。若原始發布時間無法確認，標示待核實或剔除。
- 全球焦點與市場熱門頭條須避免同一事件重複；新聞正文直接說事件、數據與市場影響，不要以「依據某媒體報導」等來源贅字開頭，來源放在新聞卡下方。
- 熱門頭條目標為 10 則，內容須混合總經、市場、企業重大消息、個股異動、財報／併購／AI／半導體；不得為湊滿數量而使用普通報價、殖利率數字、行情快訊或低重要性故事冒充新聞。若合格新聞不足，明確說明不足，不得灌水。
- 不同區塊的新聞應有明確功能與事件區隔，避免重複摘要同一報導。

## 6. 經濟與財報行事曆
- 分清「已公布／已發布」、「今日公布」、「即將公布」；依台灣時間實際發生日期更新分類。
- 事件已發生後不得仍留在「即將公布」；需移至已公布並核對實際值、預期值與前值（若可靠資料可得）。
- 公司財報應區分美股盤前、盤後及台灣實際日期；優先以公司投資人關係（IR）正式公告確認時間，再用可靠財報日曆補充。
- 清楚標示重要事件的台灣時間；未核實的發布時間、實績、共識或前值標示待核實。
- 行事曆為重要事件精選時，必須標明精選範圍，不可宣稱是全市場完整清單。

## 7. 呈現與語言
- 指數／匯率／貴金屬等名稱中文在上、英文代碼小字在下，不加括號；保留報價與漲跌幅（以可核實數據為前提）。
- 新聞摘要忠實反映原文，提供可直接開啟的原始連結；不可編造標題、連結、時間或內容。
- 報告保持既有金融資訊版面與互動，不因製作方便而縮短或刪除必要區塊。

## 11. 總結與 📌 圖釘評論撰寫規則（由原 TAC_work_rules.md 合併）

### 11.1 總結撰寫原則
1. **簡短、扼要、精準。** 總結是市場判讀，不是行情表的文字版；原則上控制在 4–5 個重點，每點以一至兩句說清楚。
2. **不重複抄寫漲跌幅與點位。** 各指數、ETF、債券、匯率、能源及貴金屬的數值已在各自行情版面呈現，總結除非數字對判斷不可或缺，否則不再逐項列出。
3. **只回答有決策價值的問題：** 市場主軸是什麼、漲勢是否廣泛、跨市場是否同步、主要風險在哪裡、接下來什麼事件可能改變判斷。
4. **先講結論，再講原因與風險。** 避免冗長背景、重複形容詞、同義句、空泛套話及為了填滿篇幅而加入的內容。
5. **提出有條件的操作結論。** 說明何種訊號值得等待、哪些風險需要控制；不得把單日行情直接寫成趨勢確立，也不得給出缺乏資料支持的確定性預測。
6. **只使用已核實資料。** 日期、交易時段、指數口徑、數據來源與市場事件須先核對。未核實的資料不得寫成確定事實，也不可用舊值或盤中價冒充最新正式收盤。
7. **與版面其他區塊分工。** 詳細行情留在行情區、事件與數字留在行事曆／財報區；總結負責整合資訊、解釋意義、指出風險與下一步觀察重點。
8. **資料更新後同步檢查。** 若行情、FedWatch、新聞、財報或經濟數據有變動，須檢查總結及相關觀察文字是否仍然一致，刪除過時結論。

### 11.2 📌 圖釘評論撰寫原則
1. **評論不能只是重述數字。** 行情表已呈現點位與漲跌幅；圖釘評論應解釋「可能的驅動因素、這代表什麼、後續看什麼、投資人如何應對」。
2. **避免贅字與重複描述。** 不要在同一區塊再次列出整串漲跌幅，也不要把相鄰版面已清楚顯示的數據重新抄一遍。只有在比較、排序或論證不可或缺時，才引用最少量的關鍵數字。
3. **每則評論要有該資產／市場的專屬觀點。** 股市談市場廣度、權值集中與區域分化；產業談輪動是否擴散；債市談期限結構與利率預期；匯率談貨幣對差異與利差；原油談供需、供應風險與通膨傳導；貴金屬談美元、實質利率、避險及工業需求。不得用一段通用文字套用所有版面。
4. **形成完整但精簡的分析鏈：** 已觀察到的現象 → 有來源支持的可能原因 → 後續驗證條件／風險 → 審慎的投資應對。推論須與已知事實區分，不得把相關性直接寫成因果。
5. **保持數據與文字一致。** 若價格下跌，不得寫成當日急升；若不同來源的時間或口徑不同，須明確說明，不可混用現貨與期貨、盤中與收盤、不同合約月份或不同市場時區。
6. **以來源報導為基礎，忠實摘要。** 新聞與市場評論應先閱讀原始報導／可靠來源，再以自己的文字濃縮其主要觀點；不可自行杜撰新聞、原因或引述來補足篇幅。
7. **不確定時明確標示。** 證據不足就寫明尚待確認，並指出需要觀察的資料；不可用空泛推測代替查證，也不可把市場隱含機率寫成央行決策。
8. **更新必須連動。** 任何行情或數據修正後，逐一檢查受影響的圖釘評論、總結、今日市場觀點、核心觀察及相關摘要，修正互相矛盾或已過時的敘述。
9. **篇幅以資訊密度為準。** 每則圖釘評論以一段精煉文字為原則；刪除重複數字、無法驗證的推測、空泛警語及與該版面無關的內容。

## 13. 五個高風險市場指標｜GitHub 擷取備案與衝突裁決規則（2026-10-28）

### 13.1 固定執行流程
1. 優先使用已建立的 GitHub Actions 擷取流程，保存 Workflow Run ID、執行結果、台灣時間、來源頁面截圖／產物、原始回應或 JSON、錯誤訊息與資料日期。

4. 截圖須能辨識來源、指標名稱、日期／時間及數值。若畫面只有數字而無法確認指標身分、日期或價格口徑，不算驗證完成。

6. 擷取流程的「成功」只代表工作執行完成，不代表數據已通過驗證。測試分支的 capture-only／source-probe 工作不可直接視為正式生產資料，也不可未經核准就寫入正式首頁或母版。

### 13.2 各指標來源優先序與特別限制
- **VIX：** 優先 Cboe 官方資料；Yahoo Finance `^VIX` 可作備援，Google Finance 等來源僅作交叉核對。官方與第三方不同時，先核對交易日、正式收盤／盤中口徑、延遲及修正情況。若確認是同一交易日的正式收盤值，採用 Cboe 值並記錄差異。

- **CNN Fear & Greed：** 優先 CNN Business 官方指數頁及 CNN 官方資料端點；FGScore 等第三方只作核對。必須確認更新時間、數值與評級一致；不同更新時點的數值不得直接視為衝突或混用。
- **SOX：** 優先費城半導體指數的可核實正式資料；Investing.com 與 Yahoo Finance `^SOX` 可作備援／交叉核對。確認指數身分、交易日、正式收盤口徑及資料是否延遲或修正；未能確認的官方頁面數值不得直接採用。
- **CME FedWatch：** 優先 CME 官方 FedWatch 機率資料。若官方頁面無法讀取，改試 CME 官方頁面的瀏覽器擷取或可核實的官方資料介面；其他網站只可輔助核對，不可冒充 CME 官方結果。必須確認會議日期、目標利率區間、機率、更新時間及各機率合計／分布是否合理；HTTP 403 或無法解析不等於機率為零，也不得自行推算填補。

### 13.3 衝突裁決順序
1. **先確認標的身分**：確定是正確指數／資料系列／會議，而非相似代號或不同商品。
2. **再確認時間與口徑**：同一交易日、同一時區、正式收盤或盤中、更新時間、現貨／期貨及合約月份必須一致。
3. **依來源權威性裁決**：同一資料口徑已確認時，優先採用指數管理機構／官方發布來源；第三方報價用於交叉驗證及發現差異，不以簡單多數決取代官方資料。
4. **調查差異原因**：檢查延遲、時區換日、頁面更新、資料修正、四捨五入、解析欄位錯位及標的錯認。
5. **無法解釋即不裁定**：不取平均、不猜測、不沿用舊值、不以「數字接近」當成證據；標記「待核實／暫缺」，並保留雙方來源和差異說明。

4. 若預定公布時間已過但未能確認正式公布、事件延期，或可信來源尚無實際值，不得自行標記為已公布或填入猜測數字；應標示「待核實」、「延期」或「實際值尚未取得」，並依已核實狀態放置。
5. 若官方資料修正、前值修正或公司更新財報時間，須同步更新事件卡、來源註記、分頁及受影響的分析文字，不得沿用過期狀態。
6. 狀態轉換驗收以事件識別碼為單位，至少確認：原事件仍可追蹤、目標分頁正確、原分頁無殘留、全頁無意外重複、實際值與時間口徑已核實。

### 16.3 已公布經濟數據卡片規格
已公布的經濟事件卡應依資料適用性呈現下列欄位；不適用或無法核實的欄位不得捏造，應明確標示未提供／待核實：
- 事件名稱、國家／經濟體、報告期間及台灣公布日期時間。
- 實際值（Actual）。
- 市場預期值（Consensus／Forecast）。
- 前值（Previous）；若原始來源已修正前值，須採用可核實的修正值並註明修正。
- 結果比較：高於、低於或符合預期；須有可比的實際值與預期值才可下判斷。
- 市場影響解讀：依指標性質說明對利率預期、債券、美元、股市或相關資產可能代表的意義，清楚區分已觀察事實與推論。
- 資料來源與可追溯連結；實際值、預期值及前值如來自不同來源，應分別確認口徑並標示必要來源。
- 不得把「高於預期」機械式等同利多，也不得把「低於預期」一概視為利空；須考慮指標方向、政策背景、前值修正及市場當時定價。

### 16.4 已公布財報專用版型與欄位
1. 財報事件正式公布後，必須使用「已公布財報」專用卡片版型，不得只把一般待公布事件卡的狀態文字改成「已公布」便視為完成。
2. 專用版型至少包括：
   - 公司名稱、股票代碼、財報季度／年度與報告期間。
   - 公布日期時間（台灣時間）及公布時段：盤前、盤後或待核實。
   - EPS 實際值、EPS 市場預期值、比較結果（若適用且可核實）。
   - 營收實際值、營收市場預期值、比較結果（若適用且可核實）。
   - 營收年增率／季增率及其他重要營運指標（有可靠資料且對公司有意義時才呈現）。
   - 公司財測／展望、毛利率、營業利益、自由現金流等補充欄位（僅在資料可靠且有助於解讀時呈現，不可為填版面而臆造）。
   - 股價市場反應：價格變動幅度、觀察時點與交易時段；盤前、盤後及正常交易時段數字必須分開，不得混為同一個「當日漲跌幅」。
   - 一句精簡業績結論、必要的市場反應解讀，以及公司正式公告／投資人關係（IR）或可靠財報來源連結。
3. EPS 與營收的實際值、預期值必須分開呈現。只有在數值、單位、財報期間及口徑可比時，才可標示「優於／符合／低於預期」；預期值無法取得時明確標示「市場預期未取得」，不得自行補值。
4. 必須清楚區分財報期間與資料類型；正式季度／年度財報、公司自結或初步數字、月營收及其他營運公告不得互相冒充。月營收公告不等同正式季度財報已發布。
5. 股價反應必須附觀察時點及交易時段。尚未開盤、尚無可核實行情或反應時間不明時，標示「股價反應尚未確認／資料未取得」，不得將前一交易日收盤變動冒充財報公布後反應。
6. 財報超出預期不代表股價必然上漲，低於預期也不代表股價必然下跌。評論應依實際業績、公司指引、預期差異及可核實市場反應撰寫；原因不足以確認時，應標示可能因素或待核實，不得杜撰因果。
7. 若某項欄位不適用或來源尚未提供，保留版型的資訊層級並標示「不適用」、「未取得」或「待核實」；不可用猜測值填滿，也不可因缺欄位而退回一般事件卡版型。

### 16.5 來源、數據與文字一致性
1. 經濟數據優先核對官方發布機構；公司財報優先核對公司投資人關係（IR）頁面、正式財報／新聞稿及監管申報文件，再以可靠財經資料源核對市場預期與股價反應。
2. 實際值、預期值、前值、財報期間、幣別、單位、每股／稀釋 EPS 口徑、股價反應時段等必須一致且可比較；不可將不同期間、不同口徑或不同來源的數字直接拼接。
3. 所有未取得、尚未公布或無法核實的欄位須如實標示。不得用空值冒充零、用舊值冒充最新值，或把推論寫成已確認事實。
4. 行事曆內容更新後，須同步檢查總結、📌 圖釘評論、今日核心觀察及其他相關區塊，避免分析仍引用過期事件狀態或錯誤數字。

- [ ] 已公布財報均使用專用版型，EPS／營收實際值與預期值、財報期間、公布時段、股價反應及來源欄位均已檢查。

- [ ] 手機與桌面版的分頁切換、卡片顯示、展開／收折與版面溢位均已檢查；未實際測試的裝置行為不得宣稱已通過。

## 17. 母版來源強制鎖定與失敗即停止（2026-10-29）
1. 唯一權威來源是 `母版專區/mother-template-manifest.json`，其核准路徑必須與第 1 節完全一致。若本文件、README、manifest 或使用者最新指示互相矛盾，以使用者最新明確指示為最高優先；先修正文件一致性，再開始製作。
2. 製作程序開始時，先根據台灣報告日期計算星期，再從 manifest 讀取唯一對應來源；不得用模糊搜尋、檔名排序、最近修改時間、GitHub 搜尋結果或聊天記憶決定母版。
3. 必須確認來源路徑存在、檔案 SHA 與 manifest 完全相符，並驗證必要區塊：頁首／日期、導航、總結、市場情緒、新聞、全球市場、產業債匯商品、適用的行事曆、今日關鍵價位、資料來源、互動腳本與頁尾。

7. 驗證失敗時不得改用首頁、歷史報告、preview 檔、其他分支或另一份母版作為備援。必須停止、回報失敗項目並等待來源修復或使用者指示。
