# Repeat Group 控制規則草案 v1

狀態：測試專區草案，未經使用者核准，不構成正式 WR，也不授權每日自動寫入。

## 目的

每日新聞、經濟事件與財報卡的筆數可能變動，但不能因此讓資料更新器任意增刪 DOM、重建整張卡片，或破壞收合與互動控制。本規則定義未來差異比對可接受的「受控重複群組」。

## 三種群組類型

### 1. 固定筆數群組（fixed）

筆數及順序均由正式母版規格固定，更新器只可更新既有子項的資料欄位，不可新增、刪除、重排或改變子項結構。

目前候選：
- 全球焦點新聞：5 則。
- 市場熱門頭條：10 則。
- 全球主要市場行情列：美國 5、亞洲 6、歐洲 3。
- 11 大產業 ETF：11 列。
- 美債：3 列；外匯：6 列。
- FedWatch 機率卡：2 張。
- 市場情緒四個 sbox：4 個；今日觀察三個 focus-panel：3 個。

### 2. 模板基準筆數群組（template_baseline）

週一與週二至週五母版本身有合法差異，不能用單一跨模板常數。每日更新仍須先保留各自母版所定義的固定骨架；在 repeat-group 差異比對功能完成前，不得因資料筆數不同而增刪卡片。

目前候選：
- 本週經濟行事曆：週一母版基準 12 張；平日母版基準 16 張。
- 本週財報行事曆：兩版基準各 16 張。
- 週一上週經濟行事曆：基準樣本 3 張。
- 週一上週財報行事曆：基準樣本 7 張。

以上數字只描述鎖定母版現況，不代表每週實際事件筆數必須固定為此數量。

### 3. 內容筆數可變群組（content_variable）

新聞或行事曆內容的實際筆數可能隨日期改變。只有在使用者核准 repeat-group 規格、差異比對器與瀏覽器驗收全部完成後，才可允許新增或移除重複子項。

目前候選：
- 本週經濟事件卡。
- 本週財報卡。
- 週一上週經濟事件卡。
- 週一上週財報卡。

## 允許的未來操作邊界（尚未啟用）

1. 重複群組外層容器、tab radio、label、nav、panel、details/summary、紅圓加號、欄位標籤、來源收合、CSS 與 JS 一律固定。
2. 每種 repeat-group 必須指定唯一容器 selector、子項 selector、子項完整 DOM 指紋、必要欄位 selector、可變筆數上下限及模板適用範圍。
3. 新增子項只能以同一正式母版中已核准的完整子項骨架複製，不得自行拼裝 HTML 或從其他模板搬用。
4. 移除子項只限於核實後不應出現的資料卡；不得移除最後一張以致失去空狀態／卡片骨架，除非另有核准的 empty-state 元件規格。
5. 每張子項的結構指紋必須一致；只允許核准資料欄位中的文字、連結與明確資料屬性變動。
6. 每張卡的收合控制、summary、欄位 label、來源區與 aria／互動屬性必須保留。
7. 任何新增／移除導致固定祖先、同層非 repeat 子項、互動控制或 CSS/JS 改變，均視為失敗並停止。
8. 每次 repeat-group 數量變動都必須留下新增／移除項目清單、理由與資料來源；不可靜默調整。
9. 若母版 SHA 與 manifest 不一致，或模板結構指紋不符，立即停止，不得寫入或部署。

## 差異比對器設計要求

未來指紋比較不得簡單忽略整個群組的 children。應採「群組外框指紋 + 每個重複子項指紋集合」：
- 群組外框與固定控制完全相等。
- 子項數量只在 content_variable 群組可變。
- 子項順序依資料排序規則驗證。
- 每個子項與其母版骨架比對，且每個子項內固定結構相等。
- 將允許變動的資料文字／href 等 payload 與禁止變動的 DOM／class／互動屬性分開比對。

## 明確禁止

- 不得以整個 calendar／earnings 容器 innerHTML 覆蓋方式更新。
- 不得將一張卡的資料內容與卡片骨架混為一體。
- 不得把週一與平日母版合併成一套共用結構。
- 不得為了讓測試通過而修改正式母版、manifest、首頁或正式 WR。
- 本草案未經使用者核准與完整測試前，不得啟用 repeat-group 自動增刪、開發母版產生或每日更新。

## 後續驗收門檻

- [ ] 每個 repeat-group 的容器與子項 selector 唯一命中。
- [ ] 週一／平日母版分別建立 baseline 子項指紋。
- [ ] 測試合法增加、合法移除、順序變動與非法骨架變動。
- [ ] 測試 details/summary、紅圓加號、tabs、aria 與手機版互動未受影響。
- [ ] 瀏覽器 DOM 測試通過。
- [ ] 使用者明確核准後，才可考慮建立測試用開發母版。
