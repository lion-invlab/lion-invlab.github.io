# TAC Weekly Calendar Database｜WR v3.7 變更提案

狀態：待使用者核准；本文件不是正式 WR，不取代根目錄 `TAC_WORK_RULES.md`。

## 提案目的
建立每週經濟行事曆與財報行事曆的持續更新資料庫，避免週一至週五反覆重建資料、事件遺漏或同一事件在不同日報口徑不一致。

## 擬新增規則
1. 每週以 ISO-8601 week ID 建立唯一資料檔，例如 `2026-W45.json`；經濟與財報事件共存於同一週檔案的獨立集合。
2. 週一初始化整週候選事件；週二至週五以穩定事件 ID 執行 idempotent upsert，不得重複新增同一事件。
3. 每日早報從週資料庫依報告日期與狀態產生日快照。每日審核／發布快照不可被後續週資料庫更新覆寫。
4. 下週一引用前一週資料檔作為歷史來源；上週區塊只顯示已公布且 TAC 五星事件。本週區塊只顯示 TAC 四星與五星事件，完全沿用 WR v3.7 星等規則。
5. 事件時間一律保存為含 UTC offset 的 ISO-8601 timestamp，顯示時區固定 Asia/Taipei；未知時間必須明確標記，不得補猜。
6. 經濟事件保留 previous／forecast／actual／impact judgment 及來源；財報事件保留 EPS、Revenue actual／consensus、比較口徑、beat/miss、財務判讀、股價反應及各自來源。
7. 經濟與財報 coverage 分別管理。來源掃描未完成時維持 incomplete，缺漏欄位維持 pending_verification，不得將「未找到」解讀為「沒有事件」。
8. 每次初始化、更新及更正寫入 audit log；修正同一事件沿用原 ID，保留更新時間與來源。
9. 週資料庫第一階段採 Git 版本化 JSON，不引入外部資料庫服務；完成原型與連續週驗證後，再評估是否正式接入每日產報流程。
10. 本提案核准前，不得把原型當成正式產報唯一來源；既有每日 JSON 與 WR v3.7 流程仍具控制權。

## 第一階段驗收條件
- W45 週檔含 11/2–11/6 全週經濟與財報事件。
- W44 歷史週檔可供 W45 週一引用，且只輸出已公布五星事件。
- 同一事件重複 upsert 不產生重複 ID。
- 日期超出週範圍、缺少時區 offset、非法星等或缺來源 URL 時驗證失敗。
- coverage incomplete 可被保留並傳遞至每日快照。
- 日快照輸出不修改來源週檔；母版、首頁、manifest 與排程保持不變。
